Ferrite runs the backend applications your coding agents write under declared boundaries: each app can reach only the destinations and resources in its manifest. Setup installs the Ferrite CLI, connects your coding agent to Ferrite's MCP tools, and opens a trial account if you do not have one yet.

A trial account starts with $5 of credit, enough to run an app or a few for 48 hours, with no account and no card; sign in to keep them. Each app runs as one instance with 256 MiB of memory and half a CPU.

## Public setup and account sign-in

Ferrite's documentation, setup instructions, downloads, package registry, and MCP discovery are public. An agent can fetch the setup guide and open an account without signing in first:

```bash
curl -fsS https://dashboard.ferrite.cloud/agent-setup/SKILL.md
```

Deployments and private account operations use the credential stored by the CLI. The Dashboard asks you to sign in before showing accounts you own.

## One connection per agent

Register one Ferrite MCP server, named `ferrite`, per agent. The setup prompt and the shell installer build it differently and expose different tool sets. Choose one route per agent and never both, so the agent never sees two overlapping sets of Ferrite tools.

| Route | What it registers | Tools the agent gets |
| --- | --- | --- |
| The setup prompt above | `ferrite mcp-serve`, the CLI's built-in stdio adapter, in the agent you pasted it into | Local development tools and a fixed set of remote tools: account, statement, cost estimate, test, preview, fork, build status, status, logs, secrets, app discovery and description, usage, releases and deploy history, `owner_status`, `claim_url`, domain listing, and (with user confirmation) rollback, scaling, and withdrawal |
| The shell installer, with Node.js 18 or later and `tar` on `PATH` | The Ferrite plugin's MCP bridge, a Node process that forwards to the hosted endpoint, in each installed Codex, Claude Code, OpenCode, and Pi client | Every tool on the hosted endpoint, including app discovery, scaling, domains, `owner_status`, and `claim_url` |

Both routes install the checksum-verified CLI, verify an authenticated account read, and keep a working login. The setup prompt also installs the Ferrite working skill in the agent where it runs; the shell installer skips skill installation. In either setup, the CLI and the agent's MCP connection share the same endpoint-bound credential in `~/.config/ferrite/credentials.toml`, so no bearer token is stored in agent configuration files.

To install by hand from your shell:

```bash
curl -fsSL https://downloads.ferrite.cloud/install.sh | sh
```

The installer replaces any existing `ferrite` entry in Codex and Claude Code, and opens a trial account with `ferrite login --ephemeral` when no working login is stored. Pass `--no-agents`, or run without Node.js or `tar`, to install only the binary and print the manual next steps. Check your release with `ferrite --version` and re-run the installer to update.

In Ferrite, an agent opens an account first and a person keeps it afterwards with one private link. The setup prompt starts a 48-hour trial with no sign-in, and the claim link it hands back makes that trial your permanent account after one Google or GitHub sign-in. Every account draws charges from a prepaid balance: an unfunded deploy is refused with `InsufficientCredit` over MCP and `INSUFFICIENT_CREDIT` from the CLI, and applications stop when the balance reaches zero. You reach an account in the Dashboard by claiming one your agent opened, and every later agent joins it by signing in.

In an account's **Getting started** section, **Copy prompt** names the account ID, endpoint, and dashboard origin without any secret, and reuses a working login for that exact account and endpoint. Another machine joins the account with `ferrite login --sign-in`: the browser opens Ferrite's sign-in, you continue with Google or GitHub, pick the account and click **Allow**, and the CLI saves a named login for that machine. A machine without a browser can import a named token from **Settings > API tokens** with `ferrite login --credentials-file <path>` instead. Never paste a token into an agent prompt. [Connect any agent to your Ferrite account](/developers/connect-any-agent/) covers every kind of agent. The account's existing credit is enough to start; payment is not a setup prerequisite.

After signing in or importing, run `ferrite account --json` and confirm that `accountId` and `endpoint` match the dashboard prompt before connecting your agent. The CLI and its MCP adapter share that login, or you can continue on the machine that already holds it. See [Fix sign-in problems](/kb/guide/fix-sign-in-problems/#connect-the-cli-to-your-account) for credential import and recovery details. The setup prompt asks before creating another account or replacing a working login.

For the full first-app and account-claim walkthrough, see [Build an app with a coding agent](/developers/colleague-preview/).

## Before your agent builds

Before your agent builds, ask it to tell you what Ferrite is and what your application would cost each month. `ferrite cost` (MCP: `estimate_cost`) reads the cost directly from the platform and returns your balance, the deploy fee, and each application's projected monthly cost at current rates without charging or deploying anything. Every charge draws from your prepaid balance, unfunded deploys are refused, and applications stop when the balance reaches zero.

## Verify setup

```bash
ferrite --version
ferrite account --json
```

Start a new session in each agent after setup because existing sessions do not reload MCP configuration automatically.

The agent reports CLI installation, account verification, MCP configuration, and skill availability separately. Restart or rescan the agent session if tools or skills are still inactive.

## Configure a client manually

These commands register `ferrite mcp-serve`, the first route in the table above. Its tools are listed in [CLI Commands](/developers/cli-commands/#agents-ferrite-mcp-serve); the installer's bridge exposes a different surface that forwards every tool on the hosted MCP endpoint. Replace `FERRITE_EXECUTABLE` with the absolute path to your installed executable:

```bash
codex mcp add ferrite -- FERRITE_EXECUTABLE mcp-serve
claude mcp add --scope user --transport stdio ferrite -- FERRITE_EXECUTABLE mcp-serve
agy mcp add ferrite FERRITE_EXECUTABLE mcp-serve
```

`agy` is Antigravity's command. Both the Antigravity app and its CLI read `~/.gemini/config/mcp_config.json`, where the command above adds a `ferrite` entry to `mcpServers` with the executable as `command` and `["mcp-serve"]` as `args`. Antigravity needs nothing else from Ferrite: no plugin, launcher script, or bundled CLI. Save the working skill to `~/.gemini/config/skills/ferrite/SKILL.md`.

If you are starting fresh without an existing account, run one of the commands below; to reach an account you already own, run `ferrite login --sign-in` instead. Each command below creates a new account and replaces any stored login the platform no longer accepts.

- Run `ferrite login --endpoint https://mcp.ferrite.cloud/mcp --ephemeral --json` to open a trial account (`eph-` prefix) that can deploy immediately within the trial limits at the top of this page. Its applications go offline after 48 hours unless you sign in through its claim link to keep it. Check `deployNote` in the reply for how deployment behaves on the selected platform.
- Run `ferrite login --endpoint https://mcp.ferrite.cloud/mcp --id ACCOUNT_NAME --json` to create a durable account under your chosen name. It starts without credit. Check the balance with `ferrite account` and [contact Ferrite support](/kb/guide/get-help-from-the-ferrite-team/) if you need credit to deploy.

In Cursor, configure a local stdio server with the absolute executable path as `command` and `["mcp-serve"]` as `args`, and preserve existing server entries. For other clients, use their supported stdio MCP configuration.

## Claim an agent-created account

Ownership attaches at the account level: one claim makes you the owner of that account, its balance, and every app inside it.

Claiming a trial account (`eph-` prefix) gives you two choices after you sign in. **Keep this as my account** makes the trial a permanent account of your own with the same apps, URLs and data and no 48-hour deadline; its ID changes from `eph-…` to a readable one. **Move it into** an account you already own moves the trial's apps there. Either way the CLI login and every connected agent of the trial follow automatically. A durable account without an owner is simply attached to you.

1. Run `ferrite account` to confirm the exact account ID that owns the apps.
2. Get the private claim link. If your agent connects to the hosted MCP endpoint (the installer's bridge or a bearer-authenticated MCP client), ask it to call `owner_status` and, when unowned, `claim_url`, returning only `url` (never the bearer token or `web_token`). A connector on a trial mints the link the same way. If your agent connects through `ferrite mcp-serve`, have it call `remote_owner_status` and `remote_claim_url` instead. From a terminal, `ferrite claim` on an `eph-` account moves its apps into a new durable account and prints that account's Dashboard link.
3. Open the URL in your browser. The page displays the account ID, balance, and app count. Sign in with Google or GitHub, then choose **Keep this as my account** or **Move it into** one of the accounts you already own. On a standalone installation without a Dashboard claim page, enter an email address and passphrase instead. The link works once and expires after 24 hours.
4. Sign in to the [Ferrite Dashboard](https://dashboard.ferrite.cloud) with that provider account (or email and passphrase where used). Confirm that the account ID matches `ferrite account`, which moves this computer's login to the kept or receiving account by itself.
5. Open **Apps**. Every app from the trial is there, at its original URL.

If your apps span more than one account ID, repeat these steps for each account with the same verified email identity so you can switch between them in the Dashboard.

Your agent can poll `owner_status` to check for completion. It never needs your passphrase, browser cookie, or dashboard session.

Do not redeploy an app because it is missing from a different dashboard account. Compare account IDs and claim the account that deployed it. See [Claim an account your agent created](/kb/guide/claim-an-agent-created-account/) for more detail.

## What the Ferrite plugin contains

The Ferrite plugin is a portable Agent Plugins 1.0.0 bundle with a separate Claude Code manifest. It packages three components: one Agent Skill covering how to build, check, deploy, and operate a Ferrite app; an MCP server entry that starts a local Node stdio bridge to the hosted Ferrite MCP endpoint; and a setup script that installs the selected instance's CLI and connects detected agents. The shell installer downloads the plugin and runs that script whenever Node.js and `tar` are available. The plugin holds no credentials; the bridge reads the CLI's stored login.

## What setup configures

| Part | Purpose |
| --- | --- |
| Ferrite CLI | Installs without root access from `https://downloads.<base-domain>/`, verified against that instance's signed `SHA256SUMS` (the release signature must verify, and the CLI must not be older than the plugin; failed verification stops the install). If instance downloads cannot be reached, setup reports this and falls back to the CLI bundled with the plugin unless `--require-published-cli` is passed. When run from the shell installer, setup reuses the CLI the installer already verified |
| Built-in MCP adapter | Exposes local development tools and a fixed set of remote tools (account, statement, cost estimate, test, preview, fork, build status, status, logs, secrets, app discovery, usage, releases, ownership, domain listing, and confirmed rollback, scaling, and withdrawal); see [CLI Commands](/developers/cli-commands/#agents-ferrite-mcp-serve) |
| Shared credential | Binds both the CLI and the agent's MCP connection to one Ferrite endpoint and account regardless of setup route |
| Working skill | Guides the agent through local checks, deployment, and live verification |

Setup writes only to user-owned directories and preserves existing integrations. Run the prompt again to verify an installation before changing it.

The plugin's setup script also accepts `--skip-login` (install and configure without creating or checking an account), `--skip-pi-adapter` (configure Pi's shared MCP file without installing its MCP adapter), and `--bundled-cli` (install the bundled CLI without querying the instance).

## How agents should use it

- Before the first deploy of a new app, run `ferrite cost` (or `estimate_cost`) and report the deploy fee, projected monthly cost, and current account balance. On a durable account, wait for agreement before deploying.
- Use the CLI for `new`, `add`, source edits, `check`, `test`, `dev`, preview, deploy, logs, and multi-step lifecycle operations.
- Use MCP for account and app discovery, focused remote reads, and single bounded control-plane mutations. `ferrite mcp-serve` offers app discovery, usage, releases, domain listing, and ownership tools, plus rollback, scaling, and withdrawal behind `confirm: true`; use `ferrite domains add` in the CLI to bind a domain, or use the hosted MCP endpoint for domain binding, promotion, and the other control-plane tools.
- Avoid rebuilding a CLI workflow as a long chain of MCP calls.
- Treat missing CLI, version mismatch, missing login, and denied authority as separate errors with distinct recovery commands.

## Check agent connections

```bash
codex mcp get ferrite --json
claude mcp get ferrite
agy mcp list
opencode mcp list
pi list
```

Run only the command for the client you want to inspect. Keep the same endpoint and account when switching between CLI and MCP. A setup prompt from an instance uses that instance's dashboard and MCP origins and names both; public installation defaults stay on `ferrite.cloud`.
